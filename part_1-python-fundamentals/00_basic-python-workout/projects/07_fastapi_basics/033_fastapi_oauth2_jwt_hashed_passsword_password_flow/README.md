# 033: Hello, OAuth2 password flow with JWT and password hashes
> Illustrates how to use JWT and password hashes to a basic OAuth2 password flow

## Project description

This example builds a basic OAuth2 password flow in which JWT is used as the access token, and passwords are hashed.

The following packages are used:
+ [PyJWT](https://github.com/jpadilla/pyjwt): JWT management
+ [pwdlib](https://github.com/frankie567/pwdlib): password hashing

You will need to use:

```bash
$ uv add pyjwt

$ uv add pwdlib[argon2]
```



### Using JWT and password hashing with `OAuth2PasswordBearer` and `OAuth2PasswordRequestForm`

1. Start by generating the `JWT_SECRET_KEY` that will be used for signing the tokens. You can use `openssl` for that:

    ```bash
    # Generate a 32 byte random sequence (will output a 64 byte long str)
    openssl rand -hex 32
    ```
1. Declare the algorithm you'll use for the token generation (HS256).

1. Declare the expire minutes value, and set it to 30 minutes.

1. Create the users database as a data dictionary in your program. You can call it `fake_users_db`, but because this might be changed in the future for a real db, make sure that all functions/coroutines working with this fake db as a data dictionary receive a reference to the db. That will make the functions/coroutine still valid once you switch to a real db.

    Note that the database need to have a `hashed_password` field with the hashed password generated by pwdlib.

1. Define the models for your application:

    + `Token`: used to return information in your `POST /token` path operation, and therefore featuring the OAuth2 spec fields `access_token` and `token_type`.
    + `TokenData`: used to store the information encoded in the token. In this simple example, the `username` will be the only field, but in a real scenario you will find fore more *claims* stored here.
    + `User`: the model for a user, without password.
    + `UserInDB`: the model for a user, with the `hashed_password` field.

1. Declare your `PasswordHash` instance, which you will use to verify that the hashes match, or to find the hash for a given password. `pwdlib` exposes the method `PasswordHash.recommended()`, which is a convenience method to get a well configured instance.

1. To disable timing attacks, you will need to force a password validation even for users not found in the database. It is recommended that you create the hash for a dummy password using the `PasswordHash()` instance. The hash will be used in the user authentication function.

1. Declare your `oauth2_scheme` using FastAPI's `OAuth2PasswordBearer`, using `/token` as the `tokenUrl`.

1. Initialize your FastAPI app, using the usual methods.

1. Define a function `verify_password()` that takes a plain password and a hashed password and returns `True` if they match, `False` otherwise.

    While you could do this manually, note that the instance of `PasswordHash()` features a `verify()` method to do just that.

1. Define a function `get_password_hash()` that takes a plain password and returns the corresponding hash.

    This method will be useful to initialize the password of the users defined in the DB.

1. Define the function `get_user()` which will be responsible for returning a `UserInDB` instance if the giver username exists in the db, returning `None` otherwise.

1. Define the function `authenticate_user()` that takes the credentials of a user and:
    + returns the `User` if the user exists in the DB, and the given credentials match what's stored in the DB.
    + returns `False` otherwise:
      + if the user is not found in the db, the password verification should be performed with the dummy hash to disabling timing attacks.
      + if the user is found, but the passwords don't match.

1. Define the function `create_access_token()` which takes a data dictionary, and the expires delta (in minutes). You should:
    1. Create a copy of the data dictionary.
    1. Calculate the expiration time by calculating the current time + the given expiration time. If the expiration time is not given a sensible default (15 minutes) will be used.
    1. Update the given data dictionary with a field `exp`, which according to the specs should represent when the token will expire.
    1. Encode the resulting dictionary in a JWT using PyJWT's `encode()` method. You should use the `SECRET_KEY` and HS256 algorithm mentioned at the beginning of your progream.
    1. Return the JWT

1. Define the `get_current_user()` dependency. This coroutine will receive the token via a sub-dependency on `oauth2_scheme`. Within the coroutine you should:
    1. Declare an instance of `HTTPException` with status code 401, detail "Could not validate credentials", and header "WWW-Authenticate" set to "Bearer". This is a convenience to prevent duplication.
    1. Set a try-except block for `InvalidTokenError`. Within this block you should:
      1. Get the payload (contents) from the token using PyJWT's `decode()`. You will need to pass the `SECRET_KEY` and algorithm defined at the beginning of your program.
      1. The payload is a dictionary. Extract the `sub` field (if available), using `None` as the default value.
      1. If the `sub` field is not found, raise the HTTPException
      1. Otherwise, set up an instance of `TokenData` with the information extracted from the JWT's payload.
    1. If the `InvalidTokenError` is raised, raise the HTTPException.
    1. Get the `UserInDb` instance whose username matches the one in the token.
    1. If the user is not found in the DB, raise the HTTPException.
    1. Otherwise, return the corresponding filtered `User` (no need for the hashed_password).

1. Define the `get_current_active_user()` dependency, which get the `current_user` via sub-dependency on the `get_current_user()`. In the function you should simple raise an HTTPException 400 with detail "Inactive user" if the user has been disabled, and return the `User` instance otherwise.

1. Define the path operation for `POST /token`. In the path operation you should declare a dependency to `OAuth2PasswordRequestForm` so that you don't need to declare the login form yourself. Then, you should:
    1. Authenticate the user using the data received in the form.
    1. If the user could not be authenticated, you should raise an HTTPException 401 with detail "Incorrect username or password" and header "WWW-Authenticate" set to "Bearer".
    1. Declare a variable to store the timedelta for the token using the value defined at the beginning of your program (30 minutes).
    1. Create an access token passing `{"sub": username}` as the data to encode.
    1. Return a `Token` instance with the results.

1. Then, define a path operation for `GET /users/me/` which requires authentication, and a `GET /items`, as a public path operation.

You can inspect the bearer in [jwt.ms](https://jwt.ms)

`InvalidTokenError` is a sort of a catch-all exception for all taken decoding errors. If your app is interested in the finer-grained errors you can explore exceptions such as `InvalidSignatureError` or `ExpiredSignatureError`.

| NOTE: |
| :---- |
| Technically, `InvalidSignatureError` and `ExpiredSignatureError` are subclasses of `InvalidTokenError`. |
